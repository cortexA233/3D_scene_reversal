# Single Mesh Lab Stage 1.5 and Stage 2 Decision Brief

Status: accepted Stone boundary restart; narrow specification ready for agent
Date: 2026-07-29

## Objective

Stage 1.5 is a blocking evidence-and-recovery phase between the frozen Stage 1 `2/4 FAIL` result and Stage 2. It exists to determine whether the failed Stone and Umbrella classes can satisfy compact code-only reconstruction, complete missing native-browser GPU evidence, repair the scalar-audit contract, and freeze trustworthy Bamboo Shoot and Mushroom acceptance boundaries.

Stage 2 remains a formal Single Mesh Lab exit path. It is not an exploratory branch that may proceed while a Stage 1.5 recovery is red.

## Invariants

- `single-mesh-quality-baseline-v1` and the historical Stage 1 two-of-four result remain unchanged.
- Stone's v1 failure remains frozen historical evidence. The unchanged 24-direction candidate may continue only under the one-time Quarantined Rebaseline defined below; its nonvisual gates remain unchanged.
- Umbrella geometry and nonvisual ceilings remain unchanged; only its new appearance candidate uses a separately calibrated patterned-appearance v2.
- New category-specific visual tolerances may be looser than Stage 1 when reference-only Calibration Brackets support the difference.
- No ordinary baseline may be loosened after candidate fitting begins. The Stone boundary review authorizes one separately versioned exception with candidate quarantine; it is not a reusable post-fit tuning mechanism.
- Authored textures, pixels, sampled lookup data, vectorized bitmaps, resolution-scaled paths, source vertices, copied source transforms, runtime textures, WASM, and unapproved Runtime Kernels remain prohibited.
- A resolved negative experiment does not satisfy a stage gate.
- This decision cycle creates no implementation code or full-island work; it creates only the three narrow Stone boundary-restart tickets required to reach a new gate decision.

## Stone boundary-review amendment

The Stage 1.5 execution reached its required stop. Stone's 24-direction
Bounded Support-plane Polyhedron passed every compactness, runtime,
determinism, and Reference Independence gate but failed six v1 geometry
thresholds. The negative certification and its metric values remain frozen;
this amendment does not reinterpret that result as a pass.

The continuation boundary is a one-time **Quarantined Rebaseline**:

- freeze the Stone generator, recipe, and existing evidence at commit
  `6ebb70c3f8162aa439377e0da46955f9f294c05f` before calibration;
- create a separately named `stone-geometry-baseline-v2`; never edit or alias
  `single-mesh-quality-baseline-v1`;
- declare the complete Authored Reference perturbation manifest, metric set,
  repeatability allowance, and threshold-selection rule before running the
  calibration;
- derive every hard threshold only from fresh Authored Reference identity,
  mild, intermediate, severe, and destructive controls; the known candidate
  metrics are prohibited calibration inputs;
- choose each limit as the least-permissive value that contains the complete
  mild envelope plus its predeclared repeatability allowance, and retain it
  only if every applicable destructive control remains outside the limit;
- replace or demote a non-separating metric before threshold freeze rather
  than moving its limit toward the candidate;
- after the machine-readable v2 baseline freezes, evaluate the exact frozen
  candidate without refitting it, first in Chrome and then through the full
  native Firefox and Safari GPU gates;
- preserve the Stone scalar, recipe, gzip, triangle, draw-call, geometry
  memory, generation-time, determinism, and Reference Independence ceilings.

The Stone-specific bracket must cover the common transform ladders plus
declared anisotropic-scale, profile-compression, and support-direction
sensitivity controls. Its destructive side must include materially squashed
or sheared forms, low-direction hull controls, and simple ellipsoid or box
substitutes. `/to-spec` must freeze exact perturbation magnitudes and the
repeatability allowance before calibration.

This is a single restart, not an iterative tolerance search. Calibration stops
if mild and destructive classes overlap. If the frozen candidate fails v2,
the project may not lower Stone thresholds again; a new boundary review must
choose between a larger representation/data budget and ending the formal
Code-only exit path. If it passes all three browsers and unchanged nonvisual
gates, Stage 1.5 resumes at patterned-appearance v2 calibration.

## Stage 1.5 execution order

Stage 1.5 is strictly sequential and stops at the first failed kill gate.

### 1. Freeze the postmortem and repair evidence contracts

- Retain [single-mesh-stage-1-postmortem.md](./single-mesh-stage-1-postmortem.md) as the factual Stage 1 input.
- Change Object-specific Scalar evidence to cover recipe, Object Generator, generated shader source, and object-specific helpers.
- Allow exclusions only for documented universal algorithm or control-flow constants.
- Rerun all four Stage 1 object audits before relying on scalar headroom.
- Keep every existing scalar ceiling unchanged.

Kill condition: the audit cannot classify production constants consistently, or an accepted object exceeds a frozen budget without an in-budget representation.

### 2. Qualify the Native GPU Visual Gate

Use the already-accepted Stone Path and Vase candidates to prove the Firefox/Safari path before new fitting work.

Each browser run must:

- be a real hardware-accelerated Firefox or Safari browser;
- explicitly reject SwiftShader, software rendering, and engine shells;
- render fresh Authored Reference and replacement captures in the same browser;
- use the fixed twelve views and complete evaluation pass set;
- run at least two independent stable capture repetitions;
- apply the object's accepted Quality Baseline in-engine;
- record browser, OS, Three.js, GPU, WebGL renderer, color configuration, and acceleration state;
- preserve CPU structure and bounds evidence as a separate complementary check.

Kill condition: Stone Path or Vase cannot produce stable in-browser reference evidence or cannot pass its frozen baseline on supported native Firefox or Safari.

### 3. Recover Stone with one distinct representation

The sole second compact candidate is a Bounded Support-plane Polyhedron:

- at most 24 fixed canonical support directions;
- compact support distances plus bounded whole-form orientation and seeded-deformation controls;
- no arbitrary source-derived face normals;
- no expansion of the direction set after fitting;
- no additional loft rings presented as a distinct representation.

The reference is a credible convex target: measured convex-hull excess is about 0.0032% by volume and 0.00035% by area.

Stone must pass:

- the complete v1 geometry gate;
- the complete v1 appearance gate after geometry passes;
- at most 32 Object-specific Scalars;
- at most 1 KB recipe JSON and 4 KB gzip production delta;
- at most 320 triangles, one draw call, 24 KB geometry memory, and 5 ms warm-generation p95;
- deterministic generation and Reference Independence;
- normative Chrome plus native Firefox and Safari visual gates.

Recorded outcome: this gate failed and triggered the boundary review. The
frozen candidate may now proceed only through the Quarantined Rebaseline above;
Umbrella v2 work still does not begin until that restart passes.

### 4. Calibrate patterned-appearance v2

Umbrella v1 remains historical failure evidence. Before fitting a new appearance candidate, create a separately versioned Patterned Appearance Baseline v2 using only Authored Reference perturbations.

The Calibration Bracket must establish:

- identity and repeated captures pass;
- declared mild motif position, phase, scale, layout, and palette changes pass;
- a flat canopy fails;
- a wrong dominant palette fails;
- deletion of a major flower, leaf, or branch motif family fails;
- materially reduced pattern coverage, including a 50% reduction control, fails;
- large phase or pattern-scale errors fail.

v2 may be materially looser than v1. It freezes only when mild and destructive classes remain separable. If an existing metric cannot separate them, `/to-spec` must make it diagnostic or replace it before fitting; the response may not be to loosen it until both classes pass.

Kill condition: no falsifiable Calibration Bracket can be frozen under the fixed capture protocol.

### 5. Recover Umbrella appearance without changing geometry

Retain the passing radial geometry, Reconstruction Frame, semantic hierarchy, and two-render-batch construction. Replace only the appearance representation with a Bounded Semantic Pattern Program.

Allowed appearance vocabulary:

- semantic canopy coordinates;
- analytic flower, leaf, branch, border, and palette motifs;
- a fixed-cap set of compact vector or Bezier controls;
- layering, symmetry, repetition, and domain transforms;
- deterministic procedural variation that does not affect topology or semantic structure.

Forbidden appearance data:

- authored or generated runtime textures;
- DataTextures, lookup images, pixels, sampled grids, or quantized image payloads;
- resolution-scaled vector paths or a vectorized bitmap;
- sampled appearance hidden in arrays, generated shader strings, or helper constants.

Umbrella must pass:

- its unchanged v1 geometry gate;
- frozen patterned-appearance v2;
- at most 96 complete-source Object-specific Scalars;
- at most 2 KB recipe JSON and 10 KB gzip production delta;
- at most 5,760 triangles, two draw calls, 256 KB geometry memory, and 12 ms warm-generation p95;
- deterministic generation and Reference Independence;
- normative Chrome plus native Firefox and Safari visual gates.

No appearance-scalar allowance is presumed from the old `86/96` report. Headroom is determined only after the corrected audit measures the frozen geometry and all generated shader constants.

Kill condition: the candidate cannot pass the frozen v2 and unchanged nonvisual boundary. Stage 2 remains closed and the project revisits whether hero patterned identity is compatible with the full-island Code-only Production Runtime target.

### 6. Pre-calibrate Stage 2 objects

Bamboo Shoot and Mushroom receive separate Category-specific Quality Baselines and separate budgets. Their baselines share one protocol and are frozen together only after both Calibration Brackets pass. Neither candidate may be fitted before both are frozen.

Common transform ladders:

| Perturbation | Mild | Intermediate | Severe |
| --- | ---: | ---: | ---: |
| Uniform scale | +/-1% | +/-2% | +/-5% |
| Canonical pivot offset | 0.01 | 0.05 | 0.10 |
| Rotation | 1 degree | 3 degrees | 5 degrees |

Mild controls define the should-pass side, severe and destructive controls define the must-fail side, and intermediate controls establish ordering without a predetermined pass result.

#### Bamboo Shoot Calibration Bracket

Source facts: 17 connected components, 60 boundary edges, open geometry, 424 triangles, and an authored base-color texture. Component analysis shows one dominant axial body plus low-complexity lateral and crown elements rather than 17 equally complex forms.

Object-specific geometry ladders:

- taper or radial scale: +/-2%, +/-5%, +/-10%;
- sheath tilt or twist: 2, 5, and 10 degrees;
- axial spacing and total-height proportion: +/-2%, +/-5%, +/-10%.

Required destructive controls:

- delete the largest non-core sheath;
- reduce visible layering by about 25%;
- collapse the open separated construction into one closed cone;
- remove the flared element with the greatest silhouette contribution;
- replace appearance with a flat color;
- corrupt the dominant palette;
- delete a major appearance motif family;
- reduce appearance coverage by 50%.

#### Mushroom Calibration Bracket

Source facts: five closed connected components, each representing one complete repeated organic form with similar topology but materially different size, placement, and orientation. Their approximate heights are 7.02, 5.92, 4.95, 4.48, and 2.99 authored-scene units.

Object-specific geometry ladders:

- per-form height and cap diameter: +/-2%, +/-5%, +/-10%;
- cap/stem proportion: +/-2%, +/-5%, +/-10%;
- lean or azimuth: 2, 5, and 10 degrees;
- relative placement: 0.01, 0.05, and 0.10 canonical units;
- light, intermediate, and severe cap radial-resolution reductions declared before calibration.

Required destructive controls:

- delete any visible member;
- collapse five forms into one giant form;
- homogenize all members to the same height, orientation, and proportion;
- materially exchange the highest and lowest members' scale or layout roles;
- delete a cap or stem's principal visible region;
- replace appearance with a flat color;
- corrupt the dominant palette;
- delete a major appearance motif family;
- reduce appearance coverage by 50%.

If a metric cannot separate mild from destructive controls, it becomes diagnostic or is replaced before candidate fitting. A candidate failure can change neither baseline.

### 7. Certify Stage 1.5

The Stage 1.5 certification must state all of the following independently:

- Stage 1 v1 remains `2/4 FAIL`;
- complete-source scalar audit is trustworthy and all retained candidates meet their ceilings;
- Stone's historical v1 failure remains recorded and the frozen candidate passes `stone-geometry-baseline-v2` in Chrome, Firefox, and Safari;
- Umbrella passes its geometry contract and patterned-appearance v2 in all three browsers;
- Stone Path and Vase have native Firefox/Safari visual evidence;
- Bamboo Shoot and Mushroom baselines and budgets are frozen before fitting;
- no runtime texture, WASM, authored appearance data, or new Runtime Kernel entered production.

Only a fully green certification authorizes Stage 2.

## Frozen Stage 2 nonvisual budgets

| Budget | Bamboo Shoot | Mushroom |
| --- | ---: | ---: |
| Object-specific Scalars | <= 64 | <= 96 |
| Recipe JSON | <= 1.5 KB | <= 2 KB |
| Production gzip delta | <= 6 KB | <= 8 KB |
| Triangles | <= 1,536 | <= 3,840 |
| Draw calls | <= 2 | <= 2 |
| Geometry memory | <= 96 KB | <= 192 KB |
| Warm generation p95 | <= 8 ms | <= 10 ms |

Six-object aggregate gates:

- production payload <= 40 KB gzip excluding Three.js;
- sequential warm generation <= 40 ms;
- runtime texture count = 0;
- production WASM = absent;
- determinism, Reference Independence, and Native GPU Visual Gates pass.

These ceilings freeze before candidate fitting. Looser category-specific visual tolerance cannot be purchased with more retained data or runtime machinery.

## Stage 2 strict sequence

### Bamboo Shoot first

The first representation consists of:

- one compact tapered asymmetric core;
- one lateral-sheath Axial Layer Family;
- one crown-leaf Axial Layer Family;
- compact count, profile, spacing, taper, phase, tilt, and twist controls;
- preserved open boundaries and stable semantic identities;
- no copied 17-component transform table.

Bamboo Shoot must pass its frozen geometry and appearance baseline, complete nonvisual budget, determinism, Reference Independence, and Chrome/Firefox/Safari GPU gates before Mushroom fitting begins.

If the first representation fails, a second compact representation may be proposed only from the observed failure mode. It may not introduce SDF, CSG, a general layer DSL, or a Runtime Kernel without satisfying the existing multi-object evidence triggers. Two reasonable compact failures stop Stage 2.

### Mushroom second

The first representation consists of:

- one shared tapered/leaning stem and anisotropic radial-cap generator;
- five Repeated Organic Forms with compact per-form placement, height, lean, cap ratio, orientation, and seed controls;
- stable per-form semantic identities;
- compatible output consolidated to at most two render batches;
- no source vertices, per-form source meshes, or copied full transform matrices;
- explicit variation rather than five identical clones.

Mushroom must pass its frozen geometry and appearance baseline, complete nonvisual budget, determinism, Reference Independence, and Chrome/Firefox/Safari GPU gates.

If the first representation fails, a second compact representation is selected only from the observed failure mode. SDF is not pre-authorized. Two reasonable compact failures stop the formal exit path.

## Exit semantics

A successful Stage 2 produces a **Versioned Category Exit**, not a retroactive Stage 1 recovery.

Required report language:

> Single Mesh Lab exit: PASS under versioned category-specific baselines (6/8 required references).

The report must list the applicable baseline version for Stone Path, Stone, Vase, Umbrella, Bamboo Shoot, and Mushroom. It may not combine mixed baselines into one aggregate quality score, and it must preserve the historical statement that Stage 1 v1 was a two-of-four failure.

## `/to-spec` handoff requirements

The next specification may decompose this brief into acceptance operations, but it must preserve the decisions above. In particular, it must specify:

- the complete-source scalar-classification and whitelist contract;
- exact native-browser version and hardware-evidence capture fields;
- the full reference-only perturbation manifests;
- the numeric patterned-appearance v2 values produced by its Calibration Bracket;
- the numeric Bamboo Shoot and Mushroom baseline values produced by their brackets;
- stable report schemas and failing exit behavior for every kill gate;
- the distinction between a resolved experiment and a passing gate;
- the final versioned-category certification report.

The numeric Stone geometry v2, patterned-appearance v2, and Stage 2 visual
thresholds are calibration outputs, not open product decisions. `/to-spec`
must define how they are produced and frozen. Stone v2 additionally requires
the candidate-quarantine procedure above; the other baselines still freeze
before fitting. None may be invented from candidate performance.

## Explicit non-goals

- no implementation in this decision cycle;
- no change to Stage 1 v1 or its historical reports;
- no post-fit threshold relaxation except the single Stone Quarantined Rebaseline explicitly bounded above;
- no production textures, source pixels, sampled appearance, or serialized source geometry;
- no new CSG, SDF, WASM, general modeling DSL, or Runtime Kernel authorization;
- no full-island, terrain, layout, scatter, structure, or compound-object implementation planning;
- no complete island-village, Umbrella, Bamboo Shoot, Mushroom, or Stage 2 implementation tickets in this boundary cycle.
